1. Tujuan & Ruang Lingkup

Overview

RASON Monitoring adalah platform berbasis Flask untuk pemantauan, analisis, dan visualisasi operasi radiosonde multi-site (BMKG). Sistem mengintegrasikan pengambilan data dari FTP, decoding berkas (BUFR/BFR/BIN), penyajian dashboard, peta 2D/3D, serta QC metrics operasional.

Target Pengguna
Operator radiosonde, analis meteorologi, dan admin sistem
Lingkup v1.0
Monitoring harian, visualisasi 2D/3D, resume data, dan QC waktu/ketinggian
Lingkungan
Jaringan internal / server on-premise; kompatibel mode offline (tanpa CDN)

2. Ringkasan Fitur Utama (v1.0)

Feature Set

Frontend & Navigasi

  • Main Page dengan menu terstruktur dan peta Indonesia (lokal asset).
  • Data Resume tabel sortable, unit di bawah header (interoperable & readable).
  • Map (MapLibre + Esri Satellite default) dengan status site & filter.
  • Trajectory 3D (Deck.gl) dengan kompas, ikon balon, dan non-loop playback.
  • Time Accuracy & Height Reach chart operasional.
  • Data Availability matriks bulanan site/jam.
  • Settings (konfigurasi FTP, path, filter) & Login/Logout.

Backend & Analitik

  • Endpoint filter: /api/filter (site, tanggal, jam, tipe file).
  • Upload/Fetch: /upload_bufr (lokal/FTP) → simpan ke uploads/.
  • Multi-site FTP crawler: fetch_all_sites dgn parsing tanggal otomatis.
  • Decoding BUFR/BFR/BIN (pybufrkit), WMO AA/BB/CC/DD generator (auto site-code).
  • QC Waktu: auto adjustment Local→UTC bila jam “preparing” ≠ 00Z/12Z.
  • Burst/Termination: deteksi ambang & mapping kode >10 (kasus Meteomodem/EoScan).
  • Hodograph (MetPy) dengan label N/E/S/W & pewarnaan ketinggian.

3. Arsitektur & Teknologi

Stack

Backend

  • Python (Flask), modular routing.
  • Flask-Login (session), akses terproteksi.
  • FTP (ftplib) multi-site, robust error handling.
  • Decoding: pybufrkit, analisis: MetPy, Matplotlib.

Frontend

  • Inter font lokal, tema konsisten (gradien biru).
  • MapLibre GL + Esri Satellite (lokal config).
  • Deck.gl untuk 3D trajectory.
  • DataTables lokal (tanpa CDN).

Operasional

  • Resource lokal → siap offline / jaringan internal.
  • Struktur folder rapi: static/, templates/, uploads/.
  • Siap kontainerisasi (Docker) & reverse proxy (Nginx).
  • Kebijakan UI responsif (desktop & mobile).

4. Penilaian Profesionalisme

Production Readiness

Kriteria Terpenuhi

  • Arsitektur modular & maintainable.
  • Konsistensi UI/UX & branding institusional.
  • Visualisasi ilmiah (Map 2D/3D, Hodograph, QC).
  • Penanganan edge-case (UTC vs lokal, burst/termination).
  • Resource lokal → kestabilan operasional.

Rekomendasi Lanjutan (Opsional)

  • Role-based access (Admin/Operator/Viewer).
  • Export otomatis PDF/DOCX laporan peluncuran.
  • Alert (email/Telegram) untuk site offline/data hilang.
  • Persist ke DB (SQLite/Postgres) untuk query cepat.
  • Docker Compose (Flask + Nginx + Redis optional).

5. Batasan Diketahui (v1.0)

Known Limitations
  • Export laporan otomatis (PDF/DOCX) masih draft.
  • Dashboard agregat lintas bulan/tahun memerlukan optimasi query FTP.
  • Belum ada database persisten untuk histori jangka panjang.
