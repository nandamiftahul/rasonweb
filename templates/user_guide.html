🛰️ OVERVIEW — SYSTEM INTRODUCTION

RASON Monitoring (Radiosonde Monitoring System) merupakan platform terpadu yang dikembangkan oleh PT. Terrindo Media Raya bekerja sama dengan BMKG untuk memantau, menganalisis, dan memverifikasi data radiosonde secara real-time dan historis.

🎯 Tujuan Sistem

  • Menyediakan pemantauan terpadu seluruh site radiosonde BMKG di Indonesia.
  • Mengintegrasikan data dari server FTP, SQLite cache, dan sistem decoding BUFR/BFR/BFH/BIN.
  • Menampilkan analisis grafis dan fisika atmosfer secara otomatis melalui antarmuka web interaktif.
  • Mendukung evaluasi performa sensor, keandalan peluncuran, serta ketepatan waktu operasional.

🧩 Arsitektur Umum

  • Backend: Flask API (Python 3.12) dengan modul decoding & QC otomatis.
  • Frontend: HTML5 + Chart.js + Leaflet + Deck.gl + MapLibre GL.
  • Database: SQLite lokal + sinkronisasi FTP radiosonde BMKG.
  • Deployment: Gunicorn + Nginx (Unix Socket), mode multi-site.

🗂️ Struktur Modul

  • 🔑 Login Page — autentikasi user dan validasi masa aktif akun.
  • 🏠 Main Page — peta nasional status radiosonde & navigasi utama.
  • 📊 Dashboard — daftar file & metadata hasil peluncuran.
  • 🗺️ Map Viewer — peta 2D lintasan radiosonde.
  • 🌐 3D Trajectory — visualisasi tiga dimensi jalur balon.
  • 🕒 Time Accuracy — analisis ketepatan waktu peluncuran.
  • 🎈 Height Reach — grafik ketinggian maksimum per site.
  • 📅 Data Availability — tabel kelengkapan data bulanan.
  • ⚠️ Error Analysis — QC otomatis berbasis fisika atmosfer.
  • ⚙️ Settings — panel konfigurasi admin & manajemen user.

💡 Pengembangan dan Pemeliharaan

Sistem ini dikembangkan secara modular agar mudah diperluas untuk integrasi data lain (misalnya Wind Profiler, Himawari IR Overlay, atau RAOB Skew-T Analysis). Semua modul dioptimalkan agar berjalan ringan di browser modern (Firefox, Chrome, Edge).

⏱️ TIME ACCURACY — DETAILED GUIDE

Time Accuracy adalah modul untuk memantau ketepatan waktu peluncuran dan durasi penerbangan radiosonde berdasarkan data hasil decoding BUFR/BFR. Halaman ini menampilkan grafik akurasi waktu dan tabel kronologi setiap peluncuran di tiap site.

🎯 Tujuan Utama

  • Mengukur deviasi waktu antara jadwal peluncuran dan aktual peluncuran balon.
  • Menganalisis durasi penerbangan (Launch → 100 hPa → Burst).
  • Memantau kepatuhan operasional site terhadap standar waktu internasional (00Z / 12Z).

🧭 Komponen Utama

  • Sidebar Navigasi: konsisten dengan halaman lain (Data Resume, Map, Trajectory, dll.).
  • Header Box: ikon ⏱️, judul “Time Accuracy Monitoring”, jam UTC real-time, dan logo BMKG.
  • User Icon: menampilkan info user dan expiry subscription.

🗂️ Filter & Selector

  • Site: memilih lokasi peluncuran dari daftar konfigurasi API /api/sites_config.
  • Month / Year: menentukan periode analisis.
  • Launch Time: memilih waktu 00Z, 12Z, atau All untuk menampilkan kedua jadwal.

📊 Chart Visualization

  • Grafik batang (stacked bar) menggunakan Chart.js untuk menggambarkan fase waktu setiap peluncuran:
    • Putih — Preparation → Launch
    • Biru — Launch → 100 hPa (AB)
    • Merah — 100 hPa → Burst (End)
  • Setiap hari ditampilkan dua bar (00Z & 12Z) untuk mempermudah perbandingan.
  • Axis: Y menunjukkan durasi dalam menit (0–240 min).
  • Title: otomatis menampilkan site, bulan, tahun, dan sesi waktu yang dipilih.

📋 Data Table

  • Menampilkan daftar harian dengan kolom:
    • Date — tanggal dan waktu peluncuran (00Z/12Z).
    • Launch — jam aktual peluncuran (UTC).
    • AB — waktu mencapai 100 hPa.
    • Burst — waktu pecah balon.
  • Header tabel bersifat sticky agar tetap terlihat saat di-scroll.
  • Data otomatis disinkronkan dengan grafik berdasarkan filter bulan dan site.

📈 Summary Statistik

  • Menampilkan rata-rata waktu (dalam menit) dari:
    • Preparation–Launch
    • Launch–AB (100 hPa)
    • Launch–End (Burst)
  • Nilai rata-rata muncul otomatis di bawah grafik setelah pemuatan selesai.

⚙️ Fitur Tambahan

  • Compact Sidebar: dapat disembunyikan (☰ / ❮) dan posisinya disimpan di localStorage.
  • Auto Update: Dropdown bulan & tahun langsung memuat ulang data secara dinamis.
  • UTC Clock: diperbarui tiap detik di header.
  • Footer: tetap di bawah dengan logo Powered by Terrindo.

Modul ini membantu operator dan supervisor memastikan jadwal peluncuran radiosonde berjalan tepat waktu dan konsisten antar site, serta menyediakan indikasi awal terhadap keterlambatan atau anomali waktu peluncuran.

🎈 HEIGHT REACH — DETAILED GUIDE

Height Reach Graph menampilkan ketinggian maksimum yang dicapai oleh balon radiosonde selama penerbangan. Modul ini membantu operator menilai performa balon, gas, dan sensor pada setiap peluncuran, serta mengidentifikasi anomali seperti burst dini atau tekanan akhir yang tidak wajar.

🎯 Tujuan Utama

  • Mengamati tinggi maksimum yang dicapai setiap peluncuran (m).
  • Membandingkan performa antara sesi 00Z dan 12Z.
  • Menilai kestabilan tekanan akhir (hPa) antar periode.

🧭 Komponen Utama

  • Sidebar Navigasi: berisi menu utama (Map, 3D, Time Accuracy, Error Analysis, dll.) yang konsisten di seluruh halaman.
  • Header Box: ikon 🎈, judul Height Reach Graph, jam UTC real-time, dan logo BMKG di kanan atas.
  • User Icon: menampilkan info akun dan expiry date.

🗂️ Filter & Selector

  • Site: daftar lokasi radiosonde (Aceh, Tarakan, Ranai, dsb.) yang dimuat dari API /api/sites_config.
  • Month / Year: memilih periode data.
  • Launch Time: memilih jadwal 00Z, 12Z, atau All untuk membandingkan kedua sesi.

📈 Chart Visualization

  • Grafik garis (line chart) dengan dua kurva:
    • Biru — sesi 00Z
    • Merah — sesi 12Z
  • Sumbu X menampilkan tanggal peluncuran (hari UTC), dan sumbu Y menunjukkan ketinggian maksimum (meter).
  • Grafik bersifat interaktif dan dapat menampilkan tooltip nilai saat kursor diarahkan ke titik data.
  • Judul Otomatis: menyesuaikan dengan site, bulan, tahun, dan sesi (00Z/12Z/All).
  • Rata-rata: nilai rata-rata ketinggian maksimum seluruh data ditampilkan di bawah grafik.

📋 Data Table

  • Menampilkan hasil numerik setiap peluncuran dengan kolom:
    • Date — tanggal dan waktu peluncuran (UTC).
    • Height (m) — ketinggian maksimum tercapai.
    • Pressure (hPa) — tekanan pada titik akhir penerbangan (burst pressure).
  • Header tabel bersifat sticky agar tetap terlihat saat di-scroll.
  • Alternating rows: baris ganjil dan genap dibedakan dengan intensitas warna latar berbeda untuk visibilitas.

📊 Summary Bawah Tabel

  • Menampilkan statistik ringkasan:
    • Max Height dan Min Height — ketinggian maksimum dan minimum (m).
    • Max Pressure dan Min Pressure — tekanan tertinggi dan terendah (hPa).
  • Bagian ini diperbarui otomatis setiap kali site, bulan, atau tahun diubah.

⚙️ Fitur Tambahan

  • Compact Sidebar: sidebar dapat disembunyikan (☰ / ❮) dan posisinya disimpan di localStorage.
  • Auto Refresh: pemilihan bulan atau tahun otomatis memuat ulang data dari server.
  • UTC Clock: diperbarui tiap detik di header.
  • Footer: tetap di bawah dengan logo Powered by Terrindo.

Modul ini berperan penting dalam mengevaluasi performa sistem peluncuran radiosonde — baik dari sisi gas pengisi, volume balon, maupun keandalan sensor tekanan. Grafik ini sering digunakan untuk memverifikasi efisiensi peluncuran dan mendeteksi potensi masalah pada sistem pengisian atau pelepasan.

📅 DATA AVAILABILITY — DETAILED GUIDE

Data Availability menampilkan ketersediaan data radiosonde per site dan per hari dalam format tabel kalender. Setiap sel menunjukkan status ketersediaan data untuk sesi 00Z dan 12Z dengan kode warna dan tooltip informasi.

🎯 Tujuan Utama

  • Menilai kelengkapan data peluncuran tiap site dalam satu bulan.
  • Mendeteksi hari/tanggal yang mengalami kehilangan data.
  • Mengukur konsistensi pengiriman file BUFR/BFR ke server pusat.

🧭 Komponen Utama

  • Sidebar Navigasi: tetap sama seperti halaman lain (Main, Map, 3D, Time Accuracy, dll.).
  • Header Box: ikon 🎈, judul Data Availability per Month, jam UTC real-time, dan logo BMKG di kanan atas.
  • User Icon: menampilkan profil user aktif dan tombol logout.

🔎 Filter Bar

  • Bulan: memilih bulan data yang ingin ditampilkan.
  • Tahun: memilih tahun pengamatan.
  • Jam: menentukan sesi peluncuran (00Z / 12Z).
  • Load Data: memanggil API /api/data_availability?month=<m>&year=<y> untuk memuat data ketersediaan.

📊 Struktur Tabel Kalender

  • Setiap baris = 1 site (misal: Tarakan, Ranai, Cilacap, Sorong).
  • Setiap kolom = tanggal dalam bulan (1–31).
  • Isi tabel berupa simbol lingkaran berwarna dengan arti sebagai berikut:

Merah — Tidak ada data (offline / gagal upload)

Kuning — Data tidak lengkap / sebagian

Hijau — Data lengkap & valid

💬 Tooltip Informasi

  • Setiap lingkaran memiliki tooltip detail, contoh:
    00Z - uploaded 06:14 UTC (complete) atau 12Z - no file received
  • Tooltip muncul saat pengguna mengarahkan kursor ke simbol.

⚙️ Fitur & Mekanisme

  • Filter Dinamis: pemilihan bulan/tahun langsung memperbarui isi tabel tanpa reload halaman.
  • Responsif: tabel bisa di-scroll horizontal agar semua tanggal terlihat.
  • Auto Adjust: kolom site dibuat tetap rata kiri dan lebar seragam.
  • Compact Sidebar: tombol ☰ / ❮ untuk memperluas atau menyembunyikan sidebar, dengan status tersimpan di localStorage.
  • UTC Clock: jam dan tanggal UTC diperbarui setiap detik di pojok kanan atas header.
  • Footer: tetap di bagian bawah dengan tulisan Powered by Terrindo.

📤 Backend Integration

Data diambil dari endpoint API /api/data_availability yang menggabungkan hasil pembacaan file BUFR dari FTP server dan SQLite cache. API menghasilkan struktur JSON seperti berikut:

    {
      "month": 10,
      "year": 2025,
      "sites": [
        {
          "name": "Tarakan",
          "days": {
            "5": { "00": {"color": "green", "tooltip": "complete"}, "12": {"color": "red", "tooltip": "no data"} },
            "6": { "00": {"color": "yellow", "tooltip": "partial"}, "12": {"color": "green", "tooltip": "complete"} }
          }
        }
      ]
    }

Halaman ini memungkinkan pengawasan operasional radiosonde dalam skala bulanan untuk mendeteksi pola data loss dan mengoptimalkan jadwal pengiriman data dari stasiun ke pusat.

⚠️ ERROR ANALYSIS — DETAILED GUIDE

Error Analysis adalah modul paling komprehensif dalam sistem Radiosonde Monitoring. Halaman ini menganalisis performa sensor, kondisi atmosfer, dan mendeteksi anomali fisis menggunakan lebih dari 10 pemeriksaan otomatis (QC Checks) berbasis algoritma Deep Physics.

🎯 Tujuan Utama

  • Mengevaluasi kualitas pengukuran suhu, kelembapan, tekanan, dan angin.
  • Mendeteksi kesalahan sensor atau masalah peluncuran (burst rendah, freeze-out, dll.).
  • Mengenali fenomena atmosfer signifikan (tropopause, jet layer, awan Cb dll.).

  • Header Box: ikon ❗, judul Error Analysis, jam UTC real-time, dan logo BMKG.

  • Kuning (Yellow) → peringatan (lonjakan angin atau RH sangat rendah).

🧠 Deep Physics Automatic Analysis

Algoritma ini menjalankan > 10 pemeriksaan berbasis fisika atmosfer. Hasilnya ditampilkan dalam dua kategori utama :

  • ⚠️ Potential Operational Issues — indikasi kesalahan alat atau peluncuran.
  • 🌍 Atmospheric Features — indikasi fenomena alam (tropopause, awan, jet stream dll.).

📋 Daftar Pemeriksaan Utama (Checks)

  1. Cold-Point Tropopause Detection: T < −75 °C → indikasi lapisan tropopause.
  2. RH Freeze-out: RH < 5 % pada T < −40 °C → sensor kelembapan beku.
  3. Pressure Reversal: kenaikan P di altitude tinggi → glitch sensor barometrik.
  4. Strong Vertical Wind Shear: ΔV > 10 m/s per km → lapisan jet/turbulensi.
  5. Directional Shear: perubahan arah angin > 60°/km → frontal zone atau jet transition.
  6. Burst Low: tekanan akhir > 100 hPa → balon pecah lebih awal.
  7. RH Sensor Saturation: RH > 90 % dengan T < −40 °C → indikasi sensor kelembapan macet.
  8. Cloud Layer Crossing: RH > 99 % pada T > 0 °C & z < 3 km → lewat lapisan awan.
  9. Ascent Rate Deceleration: perlambatan naik > 50 % → melewati awan tebal / Cb.

🧾 Summary Metadata

Ringkasan peluncuran otomatis ditampilkan di atas grafik :

  • Launch Time dan End Time (UTC).
  • Max Height & End Pressure dengan satuan km/hPa.
  • Termination Code (0–6, 11, 18 dst.) dengan penjelasan (Burst, Battery, Ascent Stop, dll.).

⚙️ SETTINGS — DETAILED GUIDE

Settings Panel merupakan pusat konfigurasi administratif sistem Radiosonde Monitoring. Halaman ini hanya dapat diakses oleh akun admin dan berisi lima tab utama untuk manajemen user, konfigurasi site, pemetaan BUFR, pencarian serial radiosonde, serta sinkronisasi antara FTP dan database.

🧭 Struktur Utama

  • 👥 User Management — mengatur akun, masa berlaku, halaman akses, dan status aktif user.
  • 🌐 Site Configuration — menambah atau mengedit koordinat stasiun radiosonde.
  • 🧩 BUFR Mapping Configuration — mengonfigurasi struktur field metadata dan level data untuk decoding.
  • 🔍 Serial Lookup — mencari informasi radiosonde berdasarkan nomor seri.
  • 🗂️ FTP vs Database — membandingkan data file antara server FTP dan cache database.

👥 1. User Management

  • Menampilkan semua akun pengguna, masa aktif, halaman yang diizinkan, dan status online/offline.
  • Expired: ditandai warna merah, Expiring Soon: warna kuning, dan Active: putih.
  • Admin dapat:
    • ✏️ Mengubah password
    • 🗓️ Mengatur tanggal expiry (YYYY-MM-DD)
    • 🧩 Mengedit halaman akses user melalui modal checkbox
    • 🗑️ Menghapus user
    • 🚪 Memaksa logout user (individu atau semua user sekaligus)
  • Data user diambil dari /api/users dan status aktif dari /admin/active_users.

🌐 2. Site Configuration

  • Menampilkan daftar seluruh lokasi stasiun radiosonde lengkap dengan koordinat dan UTC offset.
  • Admin dapat menambah site baru, mengedit posisi (lat/lon), atau menghapus site.
  • Semua perubahan disimpan ke konfigurasi sites.json melalui endpoint /api/sites_config.
  • Setiap site terhubung langsung ke dropdown filter pada halaman lain seperti Height Reach dan Data Availability.

🧩 3. BUFR Mapping Configuration

  • Menentukan pemetaan antara descriptor BUFR dengan variable name Python.
  • Terdiri dari dua kategori:
    • 📘 Metadata Mapping — informasi seperti serial number, launch time, dll.
    • 📊 Per-Level Mapping — variabel vertikal seperti pressure, temperature, humidity, wind.
  • Actions:
    • ✏️ Edit / Hapus field
    • ➕ Tambah field baru
    • 💾 Export mapping ke JSON
    • 📂 Import mapping JSON untuk overwrite
  • Konfigurasi disimpan di /api/bufrmap/<site> (default global atau per site).

🔍 4. Serial Lookup

  • Memungkinkan pencarian nomor seri radiosonde (contoh: 230451).
  • Menampilkan data lengkap dari JSON database, termasuk:
    • Nomor Kardus
    • Nomor Seri
    • Lokasi
    • Tanggal Keluar / Masuk
    • Source File
  • Backend: /api/serial_lookup/<serial>.

🗂️ 5. FTP vs Database Comparison

  • Membandingkan file yang tersedia di server FTP dan di cache database lokal.
  • Filter: site, file type (.bfr/.bufr/.bfh/.bin), tanggal mulai dan akhir.
  • Tampilan dua kolom:
    • 🌐 FTP Files: daftar file di FTP server.
    • 🗃️ Database Cache: daftar file di database lokal.
  • Indikator warna:
    • 🟢 — File tersedia di kedua sisi (synced)
    • 🟡 — Hanya di FTP
    • 🔴 — Hanya di DB
  • Fungsi tambahan:
    • 📥 Insert FTP → DB (sinkronisasi manual)
    • 🔁 Re-download file dari FTP untuk refresh data
    • 🔄 Refresh tabel FTP & DB

🛡️ Role-based Access Control

  • Admin memiliki akses penuh ke seluruh tab.
  • User biasa hanya dapat mengakses tab “🔍 Serial Lookup”.
  • Hal ini dikontrol otomatis oleh API /api/whoami pada saat halaman dimuat.

⚙️ Fitur Tambahan

  • Responsive Layout: semua tabel dan input menyesuaikan layar.
  • Auto Refresh: site dan user list memuat ulang setelah setiap perubahan.
  • JSON Compatibility: mapping BUFR dapat diimpor/ekspor antar environment.

Panel ini menjadi pusat kontrol utama untuk pengelolaan user, site, dan data. Seluruh konfigurasi di sini secara langsung memengaruhi modul analisis dan visualisasi pada sistem Radiosonde Monitoring.
